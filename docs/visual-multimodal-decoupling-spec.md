# 概况与笔记的多模态解耦规格

## 目标

把“画面信息在各产物中的消费方式”显式建模。核心是三个事实：

1. **帧（图片）是唯一的画面来源，按制品生命周期可复用地保留。** 它有三个互相独立的去处：给用户看（配图）、注入下游产物（原图档）、喂视觉模型产出可检索证据。
2. **`visual.evidence` 是视觉信息的文本索引。** 它固定服务 RAG 检索，也可作为下游模型的低成本辅助输入；它的“可脱离图片理解”要求是为**文本检索**设计的。它是**索引，不是图片的替身** —— 图→文必然有损，**不得用它替代原图输入**。
3. **每个产物有两个正交的设置维度**：A「配不配图」（输出，用户可见）与 B「模型输入看什么」（输入，用户不可见）。

本规格不新增 `max_display_frames`。概况的展示帧 = 每章一张（12 章即 12 张；仅媒体无视频流等异常时例外），**不设配额**；`max_visual_frames` 只约束**读图帧**（送进视觉模型的帧）。详见“展示帧与读图帧：两个量”一节。

## 两个正交维度

### A. 配不配图（输出）

影响成品的**形态**，用户可见。取值：不配 / 配图。

### B. 模型输入看什么（输入）

影响**生成质量与成本**，用户不可见。三档：

| 档位 | 含义 | 成本 | 信息完整度 |
| --- | --- | --- | --- |
| `none` | 不看画面信息（仅转写与概况文字） | 0 | —— |
| `evidence` | 注入 `visual.evidence` **文本** | 0（概况已产出） | 有损（自然语言描述的天花板） |
| `frames` | 注入**帧原图**（多模态） | 视觉 token | 完整 |

两者必须分开：一个产物完全可以“配图但模型不看图” —— 笔记的图是**新抽的**，模型从未看过它们。

### 各产物的取值

| 产物 | A 配图 | B 模型输入 | 说明 |
| --- | --- | --- | --- |
| 概况 | 每章一张（**固定**） | `frames`（**固定**） | 它是 evidence 的**生产者**，必须读图；因此**没有 `evidence` 档** |
| 思维导图 | —— | `none` / **`evidence`** / `frames` | 知识结构主要来自转写，证据够用 |
| 知识卡片 | —— | `none` / **`evidence`** / `frames` | 同上 |
| 笔记 | 不配 / 配图（可选） | `none` / `evidence` / **`frames`** | 两个维度都有 |
| RAG（聊天检索） | —— | `evidence`（**固定**） | 只能检索文本，没有选择余地 |

加粗为默认值。

### 设置归属

本规格新增的全部配置项都落在 **`config/settings.toml` 的 `[generation]` 段**（与现有 `chapter_visual_mode`、`max_visual_frames` 同段），并需同步 `config/settings.toml.example`、`settings.py` 的类型与校验、以及设置接口的读写。

| 设置项 | 维度 | 归属 | 取值 / 默认 |
| --- | --- | --- | --- |
| 概况 `chapter_visual_mode` | A + B | **普通设置** | `off` / `screenshots` / `multimodal`（现为 `screenshots`） |
| 笔记 `note_visual_mode` | **A** | **普通设置** | `off` / `screenshots` |
| 笔记 `note_visual_input` | **B** | 高级设置 | `none` / `evidence` / `frames`（默认 `frames`） |
| 导图 `mindmap_visual_input` | B | 高级设置 | `none` / `evidence` / `frames`（默认 `evidence`） |
| 卡片 `cards_visual_input` | B | 高级设置 | `none` / `evidence` / `frames`（默认 `evidence`） |
| 笔记 `note_max_images` | A 上限 | 高级设置 | 正整数，只约束模型输出 |
| 笔记 `note_image_min_gap_seconds` | 校验 | 高级设置 | 正数，**默认 5**（见“避免与概况重复”） |

笔记的 A 维度必须留在普通设置：成品里有没有图是**用户可见**的，与“看不看画面”（不可见）性质不同。

高级设置项需要给出输入校验（取值范围、非法值提示）与默认值说明，避免用户填出无效值后只在运行时静默降级。

**实现顺序上的注意**：`config/settings.toml` 是由 `settings.py` **按 `AppSettings` 字段逐行重新生成**的（不是增量补丁），因此**不能只往 toml 里加键** —— 未知键不仅会被读取端静默忽略，还会在下次保存设置时被直接抹掉。必须先加上 `AppSettings` 字段与序列化，再写 toml 值。

### 依赖与退化

B = `evidence` 依赖概况已产出 `visual.evidence.json`；B = `frames` 依赖帧已抽取。

| 概况档位 | 有帧 | 有 evidence | 下游 `none` | 下游 `evidence` | 下游 `frames` |
| --- | --- | --- | --- | --- | --- |
| `multimodal` | ✅ | ✅ | ✅ | ✅ | ✅ |
| `screenshots` | ✅ | ❌ | ✅ | ⚠️ 退化为 `none` | ✅ |
| `off` | ❌ | ❌ | ✅ | ⚠️ 退化为 `none` | ⚠️ **退化为 `none`** |

⇒ 选 `off` 会让下游的 `frames` 一起失效；若希望下游仍能看原图，概况至少要 `screenshots`。UI 应据此置灰不可用选项，并说明原因。

## 现状基线（已核对）

当前概况链路在 `GenerateVideoSummary` 中如下执行：

1. 文本总结模型为每个章节给出 `image_timestamp_seconds`。
2. `_attach_chapter_screenshots` 按这些章节时间点抽帧，受 `max_visual_frames` 限制。
3. 抽出的帧立刻以 `image_filename` 和原时间戳回填到同一章节。
4. `LiteLLMVisualSummaryEnricher` 把这批同一章节帧发送给视觉模型，生成补强后的概况和 `visual_evidence`。
5. 前端按章节上的 `image_url` 显示图片。

因此，当前实现存在三个问题：

1. **配额被安在抽帧环节**（第 2 步），而它只应该限制读图 —— 导致 7 章及以上的视频直接生成失败（详见“展示帧与读图帧”一节的现状基线）。
2. **模型可以跳过章节**（`image_timestamp_seconds` 可为 null），与“每一章都必须有一张图”的产品形式不符。
3. **抽帧与读图在当前实现里是同一个集合**（抽了就全部送进视觉模型），没有把“展示帧”与“读图帧”区分为两个量。

## 共同基础设施（保留并复用）

下列能力是共享基础设施，不按概况或笔记重复实现：

- `FrameExtractor`：从媒体精确抽取 JPEG 帧。
- `ExtractedChapterFrame` 或其后继的不可变帧记录：帧 ID、真实文件名、真实时间戳、来源路径。
- `build_multimodal_user_content`：将文本和本地 JPEG 组装为 LiteLLM 兼容消息。
- `LiteLLMCompletionGateway` 的结构化调用与重试。
- 视觉证据校验：帧必须真实存在；同帧最多一条证据；章节/时间戳必须与系统抽帧记录一致；证据文本不能为空。
- 安全落盘与读取：任何展示 URL、文件名和时间戳均由系统从已校验帧记录回填，模型不得直接决定。

`visual.evidence.json` 保持为“已经看过图片后得到的、可脱离图片理解的文本事实”制品；它仍可进入文本 RAG。

### 刻意不统一的部分

**“图放在哪里”的表达方式**在两侧保持不同，这是有意设计，不要强行统一：

| | 位置怎么表达 | 为什么 |
| --- | --- | --- |
| 概况 | 章节字段（`chapter_frame_targets` → 回填 `image_filename` / `image_url`） | 概况是**结构化的时间轴索引**，图是章节的属性（每章一张）；用字段表达最贴合，且“每章一张”只需校验字段数量。概况本身**不可编辑**，不需要文本内标记 |
| 笔记 | 正文标记 `[[IMG:mm:ss]]` | 笔记是**用户自己的自由文档**，图是文本的一部分（位置在“这段文字之后”）；只能用标记表达，且需要支持用户自行编辑 |

共享的是**帧本身**（抽取、按秒命名、URL 生成、seek 数据），而不是**位置的写法**。两侧都必须遵守同一条不变量：**文件名、时间戳与展示 URL 只能由系统从已校验的帧记录回填，模型不得直接决定。**

## 概况多模态：每章一张图 + 受限读图

概况设置继续使用现有 `chapter_visual_mode`：`off` / `screenshots` / `multimodal`。

概况的产品形式是**每一章都必须有一张图**：12 章的概况就有 12 张图，不存在“12 章只有 6 张图”。因此：

- **抽帧数量 = 章节数，不受 `max_visual_frames` 限制**；该配额只限制**读图**（送进视觉模型的帧数）。
- **“每章取哪一刻”仍由模型逐章决策**：模型读该章转写后为该章选出最有代表性的一刻 —— 这就是“找位置”，对应下节的 `chapter_frame_targets`。**它依然需要模型判断，不能由系统用固定比例（如取章节中点）代替。**
- **但帧与章节的归属是 1:1 的**：抽帧时即按 `chapter_id` 绑定，因此**不需要独立的“展示映射”机制**（旧稿的 `chapter_display_frames` 因此取消）。这两件事必须区分：**“在章节内找时刻”要模型决策；“帧挂在哪一章”由系统绑定。**

### 1. 章节抽帧位置（两种模式共用）

文本总结阶段为**每一章**给出一个抽帧时间点：

```json
{
  "chapter_frame_targets": [
    { "chapter_id": "chapter-03", "timestamp_seconds": 84.2 }
  ]
}
```

- 条目数必须等于章节数（每章一条）；缺章、重复章视为模型输出无效；
- `chapter_id`、候选时间与章节区间必须由系统校验（时间须落在该章区间内）；
- 系统把每个条目转换为不可伪造的 `frame_id`、文件名和实际时间戳；
- 抽帧后，真实文件名与真实时间**回填到同一章节** —— 这就是展示位置，不再另设映射；
- 该计划**不受 `max_visual_frames` 限制**（它是展示帧的来源）；
- 仅当媒体确实抽不出帧（如无视频流）时该章不展示图片，属异常兜底；**不允许模型主动跳过某一章**。

### 2. 读图选择（仅 `multimodal`）

- 系统从抽出的章节帧里按确定性规则挑出至多 `max_visual_frames` 张送给视觉模型（例如按章节顺序均匀采样、首尾优先）；
- 取舍由**系统**完成，模型不参与，也不影响抽帧与展示；
- 视觉模型读到这批帧后，在**同一次结构化响应**中产出 `visual_evidence`（逐帧文字证据），不增加第二次视觉调用；
- **未被读到的帧照常展示**，但只允许中性标题（如“视频画面（01:24）”），不得作为视觉事实。

### 3. 三档行为

| 模式 | 抽帧（= 展示帧） | 读图 | 章节展示 |
| --- | --- | --- | --- |
| `off` | 不抽帧 | 0 | 不展示图片 |
| `screenshots` | 每章一张，**不设配额** | 0 | 每章展示自己那张；不可写画面事实 |
| `multimodal` | 每章一张，**不设配额** | ≤ `max_visual_frames` | 每章展示自己那张；读过的帧可写画面事实 |

`screenshots` 与 `multimodal` 的**抽帧与展示完全相同**，唯一区别是后者会读其中一部分帧、并允许据此写画面事实。两个档位都不允许依据**未阅读**的图片补充任何画面事实。（含笔记在内的完整对照见“展示帧与读图帧：两个量”一节。）

### 4. 边界

| 场景 | 处理 |
| --- | --- |
| 计划条目数 ≠ 章节数，或缺章、重复章 | 视为模型输出无效，拒绝并重试（与现有条目校验一致） |
| 某章时刻不在该章区间内 | 同上，视为无效 |
| 媒体无视频流（纯音频） | 该章不展示图片；所有章节都抽不出时，本视频不产出任何帧，下游 `frames` 档因此退化 |
| 个别章节抽帧失败 | 该章不展示图片，其余章节照常；**不使整次概况生成失败** |
| 读图（视觉模型调用）失败 | **不使概况生成失败**：保留文本概况与全部展示帧，只是本视频不产出 `visual.evidence.json`（下游 `evidence` 档因此退化为 `none`），并写入日志与进度提示 |
| 帧数 ≤ `max_visual_frames` | 全部读取，不做取舍 |
| 帧数 > `max_visual_frames` | 由系统按确定性规则取舍（章节顺序均匀采样、首尾优先） |

## 笔记配图：标记机制

笔记与概况的关系是「概况之上」：概况已经完成抽帧，笔记**复用这批帧**而不重新抽帧；笔记展示的图则是**新时刻的新帧**（见下），因此不与概况重复。

关于模型输入：笔记**默认注入帧原图**（B = `frames`），因为它会产出“界面对不对、字段叫什么”这类对画面具体元素的断言，仅靠 `evidence` 文本会丢结构化信息。`evidence` 只作为可选的补充背景。

### 设置

- **`note_visual_mode`**（A 配图，普通设置）：`off` / `screenshots`。UI 上呈现为一个开关（是否自动配图）。
- **`note_visual_input`**（B 输入，高级设置）：`none` / `evidence` / `frames`，默认 `frames`。
- **`note_max_images`**：一篇文章的插图数量上限，只约束**模型输出**的标记数量，不限制用户手写。

注意：A 与 B 相互独立 —— `note_visual_mode = "off"` 时笔记不插图，但 B 仍可注入原图以提升正文质量。

### 插图标记 `[[IMG:mm:ss]]`

笔记正文用标记声明插图位置（下方示例中的小标题写作 `#` 级，仅为避免与本文档的标题层级混淆）：

```markdown
# 配置流程

先获取 B 站 cookie。

[[IMG:00:51]]

选择「收藏夹」后点击获取视频。
```

- 语法：`[[IMG:mm:ss]]`，也接受秒数 `[[IMG:51.0]]`；
- 该标记**不与现有渲染规则冲突**（引用角标 `[数字]` 与方括号数学式正则都不会命中）；
- **存储时保留标记原文，不替换** —— 标记是唯一真源，用户改时间点即改标记；
- 渲染时才转换为图片，标题为中性文案并携带秒数供点击 seek：

  ```markdown
  ![视频画面（00:51）](/api/videos/{series}/{video}/frames/51.0.jpg "51.0")
  ```

- 帧文件**按秒数命名**（如 `frames/51.0.jpg`），天然去重：不同笔记引用同一时刻命中同一张图。

### AI 生成

- **输入按 `note_visual_input` 决定**：
  - 基础（三档共用）：转写 + 概况文字 + **概况已用时刻**（用于避让，避免笔记插图与概况重复）；
  - B = `evidence`：额外注入 `visual.evidence` 文本；
  - B = `frames`（默认）：额外注入**概况已抽的帧原图**（多模态），并可用 `evidence` 作为补充背景；
- 模型输出**自由 Markdown 正文**，在需要配图处写 `[[IMG:mm:ss]]`；
- 约束：时刻须落在视频时长内；须**避开概况已用时刻**（规则见下）；标记数量 ≤ `note_max_images`；
  **不得为插图撰写说明或做视觉指认**（模型未读过这些**新抽的**帧），包括“如下图显示…”这类句子。
  注意这与 B = `frames` 不矛盾：模型看到的是**概况的帧**，而它自己声明的是**另一时刻的新帧**。

### 用户手写

同一套标记对 `source = "manual"` 的手写笔记生效：用户可自行写 `[[IMG:00:51]]` 插图；校验只要求时刻落在视频时长内，**不受“避开概况”与数量上限约束**。

### 避免与概况重复（`note_image_min_gap_seconds`）

“不重复概况画面”必须是**可校验规则**，不能只写在提示词里。

- **配置项**：`note_image_min_gap_seconds`（`config/settings.toml` 的 `[generation]` 段，设置界面的**高级设置**，默认 `5`）；
- **规则**：笔记标记的时刻，与**概况在同一章节内已用的时刻**之间的时间差必须 ≥ 该值；不满足时按“标记无效”处理（见边界表的异常占位）；
- **为什么不用“必须落在不同章节”**：笔记的段落可能正好对应某一章，它必须在该章范围内选时刻才能与内容相关；强制换章会逼模型选不贴切的画面。“同一章内错开足够时间”既避免重复画面，又不牺牲相关性；
- 阈值越大越不容易重复，但可选范围越小；对时长过短的章节（小于 2 × 阈值）放宽为“只要不完全相同”。

### 边界

| 场景 | 处理 |
| --- | --- |
| 抽帧时机 | 保存笔记时抽帧（内容变更即重抽） |
| 时刻超出视频时长 | **保留原文标记**并标记为无效，不静默丢弃 |
| 标记格式非法（如 `[[IMG:abc]]`、括号不配对） | 同上：**按普通文本原样保留**，不猜测意图 |
| 抽帧失败 | 同上，保留标记 |
| AI 输出标记数超过 `note_max_images` | **保留前 N 个，其余标记连同其所在行一起从正文删除**，并写入日志；**不使整篇笔记生成失败** |
| 同一笔记内重复引用同一时刻 | 复用同一张帧文件（按秒命名天然支持），不额外报错 |
| `note_visual_mode = "off"` 但用户手写了标记 | **照常插入图片** —— `off` 只关闭“模型自动配图”，不限制用户手写 |
| `evidence` 档但 `visual.evidence.json` 的 frames 为空 | 等价于 `none`（并入“依赖与退化”表） |
| 用户删除标记 | 对应帧文件成为孤儿，可定期清理，不影响正确性 |
| 同一时刻被并发抽取 | 按秒命名 + 原子写，幂等；文件已存在即复用 |

### 概况重新生成后的连锁行为

- **帧**：按新计划重新抽取；按秒命名，与已有帧相同的时刻直接复用，不重复抽；
- **evidence**：重新产出，覆盖旧的 `visual.evidence.json`；
- **已生成的下游产物（导图 / 卡片 / 笔记）不自动重算** —— 笔记的“避让依据”会因此过期，但不影响正确性（图片仍在、seek 仍有效），只是可能与新概况出现画面重复；用户可手动重新生成；
- **实现要求**：下游产物需记录其生成时依赖的概况版本（或时间戳），以便 UI 提示“概况已更新，建议重新生成”。

### 为什么不再需要只读约束

旧稿曾要求“含帧引用的 AI 笔记只读”，理由是 `frame_id` / 段落位置 / 视觉证据必须保持一致。改用标记后，**图片位置就在 Markdown 里、时间锚点在标记里，引用关系随文本自身保持一致** —— 因此笔记保持可编辑，不需要只读、不需要结构化 sections、也不需要 `frame_id` 校验。这保住了笔记区别于概况的核心特征：**概况是只读的时间轴索引，笔记是用户自己的文档。**

## 展示帧与读图帧：两个量

只需要建模两个量。概况下**抽帧即展示**（1:1，不存在“抽了不展示”的情形），因此“抽帧”与“展示”是同一件事的两个说法，合并为**展示帧**。

| 量 | 含义 | 成本 | 配额 |
| --- | --- | --- | --- |
| **展示帧** | 从媒体抽出并展示的 JPEG（抽出即展示） | 本地 ffmpeg + 磁盘（约百 KB/张），**无 API 成本** | **否**（概况每章一张） |
| **读图帧** | 送进视觉模型的帧，必须是展示帧的子集 | **视觉 token —— 唯一有真实成本的一项** | **是**，由 `max_visual_frames` 约束（仅概况） |

概况的 `screenshots` 档即“只有展示帧、读图帧为 0”；`multimodal` 档即“展示帧照常 + 读图帧受配额”。**限制必须落在读图帧上，不能落在展示帧上。**

笔记不建立自己的展示帧集合（它的插图按标记单独抽取），而 B = `frames` 时**复用概况的展示帧**作为模型输入，因此不额外占用抽帧环节，也不受上面的配额影响。

概况三档的抽帧、读图与展示对照见“概况多模态”一节的“三档行为”表；笔记与下游产物的三档输入设置见“两个正交维度”一节。

### 概况

- **展示帧随章节数增长，这是产品形式，不设全局上限**，也不能因为配额被裁剪。
- **只有读图帧受 `max_visual_frames` 约束，且仅在 `multimodal` 下生效。**
- 因此 `multimodal` 会出现“展示 12 张、其中只读了 6 张”的情形，此时：
  - 12 章照常各自展示画面；
  - 只有**读过的**帧可以携带画面描述与视觉证据；
  - 未读帧按 `screenshots` 语义处理：只允许中性标题（如“视频画面（01:24）”），不得作为视觉事实。
- “读哪几张”由系统按确定性规则取舍（例如按章节顺序均匀采样、首尾优先），并写入日志；**不接受模型自行取舍，且不影响展示帧**。

### 笔记

笔记是自由文档，插图位置与数量由正文里的 `[[IMG:mm:ss]]` 标记决定，不存在结构约束，因此：

- `note_max_images` 只约束**模型输出**的标记数量，不限制用户手写；
- 笔记**不为输入抽帧**：B = `frames` 时注入的是**概况已抽的帧**，因此不占用抽帧环节，
  也与概况的读图配额 `max_visual_frames` 无关；
- 笔记**展示**的插图是**新时刻的新帧**，按秒数命名并与概况帧共用同一帧目录 ——
  同一时刻只会存在一份文件（天然去重），但笔记选的是与概况**不同的时刻**。

### 现状基线（已核对，存在生产风险）

`validate_visual_frame_plan` 在计划条目数超过 `max_visual_frames` 时**抛出 `ValueError` 终止整次生成**：

```python
if len(plans) > max_visual_frames:
    raise ValueError(f"模型选择了 {len(plans)} 张截图，超过上限 {max_visual_frames}。")
```

而提示词对模型只是**软约束**（“整个视频最多选择 `$max_visual_frames` 张；普通人物出镜、片头片尾、过场和纯口述章节必须填 null”），实测模型倾向给每一章都填：四个历史制品的抽帧数等于章节数（12/12、12/12、8/8、7/7），全部超过当时的 6。它们生成于该校验上线（2026-09-16，commit `e6a6df98`）之前，因此未被拒绝。

⇒ 在“抽帧与展示不设配额”的规格下，这个校验**从根上放错了位置**：它拦截的是抽帧/展示，而被限制的应该是读图。当前代码下，任何 7 章及以上、且被模型全选的视频，AI 概况会直接生成失败。

**改法**：把配额从抽帧环节移到读图环节 —— 抽帧与展示全量保留，只对“送进视觉模型的帧数”做取舍，且取舍由系统完成、不抛错、不影响展示。

## 错误与降级的用户可见性

**原则：任何失败或降级都必须让用户知情，不得静默处理。** 错误文案要满足三点：使用中文；说清“发生了什么”与“用户可以做什么”；不暴露内部 ID、堆栈或英文技术术语。

### 硬失败（中断当前操作）

| 场景 | 提示位置 | 文案要点 |
| --- | --- | --- |
| 概况：计划条目与章节不匹配、缺章重复章、时刻越界，重试后仍失败 | 生成进度条的错误态 | “AI 概况生成失败，请重试；若反复失败，可尝试关闭章节截图后重新生成。” |
| 笔记：模型输出无法解析（连续重试失败） | 笔记生成失败提示 | “AI 笔记生成失败，请重试。”——不暴露字段名与校验细节 |

### 降级（继续产出，但必须告知）

| 场景 | 降级结果 | 提示位置与文案要点 |
| --- | --- | --- |
| 个别章节抽帧失败 | 该章无图 | 概况中该章节内显示“本章无可用画面”，不留空白 |
| 媒体不含视频流 | 本视频无任何帧 | 概况页提示“该媒体不含视频画面，未生成截图” |
| 视觉模型调用失败 | 无 `visual.evidence.json` | 概况页提示“已完成文本概况；本次未能解析画面，画面描述暂不可用”，同时把下游 `evidence` 档置灰 |
| 概况为 `off` | 下游 `evidence` 与 `frames` 均不可用 | 高级设置中置灰这两项，说明“需先启用 AI 概况的截图” |
| 概况为 `screenshots` | 下游 `evidence` 不可用 | 置灰该项，说明“需先启用 AI 概况的视觉阅读” |
| 笔记标记超 `note_max_images` | 截断到上限 | 笔记生成完成后轻提示“已生成 N 张插图（已达上限）” |
| 笔记标记非法 / 时刻越界 / 抽帧失败 | 该标记保留为**可见的错误占位** | 渲染为“此处插图不可用（原因）”，例如“此处插图不可用：00:51 超出视频时长” |
| 下游 `evidence` / `frames` 因依赖不足而退化 | 实际按 `none` 执行 | 见上两行；退化必须在设置界面可见，不能只在运行时静默发生 |

**最后一条最容易被做错**：“保留原文标记”**不等于**把 `[[IMG:00:51]]` 原样显示给用户 —— 用户读不懂那是错误。必须渲染成可读的异常占位（含原因），同时保留原文以便用户修正。

## 实施顺序

1. **重构概况**：把配额从抽帧环节移到读图环节（抽帧 = 每章一张、不设配额）；取消章节展示映射（展示位置由抽帧时的 `chapter_id` 绑定）；改提示词，去掉“某些章节可填 null”的选项；迁移现有三道校验。
