# 工作区媒体工作流规格

## 目标

在当前工作区的架构内补齐高价值媒体工作流：人工字幕导入、按时间点截图、视频库状态筛选、批量操作和顺序调整。

本规格以当前 `src` 为实现基线。下载目录中的旧代码只作为行为参考，不能直接迁回：其中 SRT 上传没有后端实现，HTML/Word 导出函数没有调用点，字幕状态也把“已有转写”误标成“已有字幕”。

## 范围与优先级

| 优先级 | 工作包 | 用户价值 |
| --- | --- | --- |
| P0 | 手动导入 SRT | 使用已有字幕，跳过字幕探测与 ASR，修正错误转写。 |
| P1 | 时间点截图与查看器 | 在概况中快速核对关键结论对应的视频画面。 |
| P2 | 视频库筛选与批量操作 | 管理大量待处理、完成和异常视频。 |
| P3 | 视频排序 | 按学习顺序组织系列。 |

不在本期范围：Synology Drive/NAS 缓存扫描、旧版自写 HTML/Word 导出器、把图片写进原始转写文本。

## P0: 手动 SRT 导入

### 用户流程

1. 用户在已选视频的“AI 概况”中点击“导入 SRT 并生成概况”。
2. 选择一个 `.srt` 文件，确认框显示文件名。
3. 用户确认后，系统以该字幕生成 AI 概况；进度在同一个任务中展示。
4. 生成期间展示同一生成任务状态，并明确“当前仍显示上一次结果”。
5. 只有人工转写和 AI 概况都生成成功，系统才将它们一起切换为当前版本；此前的内容保持可读。
6. 任一阶段失败或被取消，当前人工转写、概况、卡片、导图和索引均不改变；取消后提示“已取消，当前内容未改变”。
7. 后续重新生成概况时，优先使用人工转写，不探测 Bilibili/内嵌字幕，也不调用 Faster Whisper 或云端 ASR。
8. 用户可执行“改用自动转写并重新生成”；自动字幕/ASR、转写和概况同样在候选版本完成后，才以新版本替换当前人工版本。确认框说明成功前仍保留当前人工版本。

### 转写来源优先级

```text
manual_srt
  -> bilibili_subtitle / embedded_subtitle
  -> ASR (faster_whisper / aliyun_bailian)
```

人工 SRT 不走 ASR。ASR 只处理不存在任何可用字幕时的视频或音频。

### 后端设计

- 复用现有 `srt` 依赖和 `Transcript` / `TranscriptSegment` 模型；不新增手写 SRT 解析器。
- 新增一个明确的“导入人工转写”用例和存储端口，不在 FastAPI 路由内直接读写制品文件。
- `POST /api/videos/{series_id}/{video_id}/transcript/srt-and-generate` 接收 `multipart/form-data` 的单个 `file`；复用既有生成任务状态接口显示进度。
- 仅接受 UTF-8 的 `.srt`；语言不作首期额外限制，以现有 `srt` 解析库和概况模型的实际能力为准。解析失败、空字幕或无效时间段时返回 `400`。
- 不提供在线编辑字幕；用户需要修改时重新上传文件。视频已有人工 SRT 时，新的上传直接替换旧人工 SRT，但仍须走完整候选版本生成，不能先覆盖旧文件。
- SRT 解析和 LLM 概况生成均在现有生成暂存目录中完成，生成期间绝不修改当前制品。
- 暂存内容包含规范的 `transcript.cleaned.json`、原始 `transcript.manual.srt`、`transcript_source = "manual_srt"` 元数据、`summary.json` 和 `summary.md`；全部写入并校验成功后，复用现有生成提交路径一次性替换当前内容。
- 成功提交时，旧知识卡、单视频/系列导图和 RAG 索引立即失效且不可读取；物理清理可异步进行，但不能影响读取语义。
- 任一解析、LLM、落盘或校验失败时删除暂存内容、不触碰当前制品。远端 LLM 调用可能已消耗额度，但本地业务状态必须完全不变。
- 导入任务应可取消：取消请求阻止后续阶段并删除候选版本；若已进入最终提交临界区则完成提交后返回最终状态，不能留下半版本。
- 更新必须持有视频内容锁，避免与生成任务并发覆盖；生成进行中时返回冲突错误。
- `POST /api/videos/{series_id}/{video_id}/transcript/restore-auto-and-generate` 启动恢复自动转写：保留当前人工版本可读，直到自动字幕或 ASR 与新概况均成功后才切换；失败或取消时继续保留人工版本。

### 前端设计

- 在单视频概况工具页提供“导入 SRT 并生成概况”和“改用自动转写并重新生成”命令；命令只在选中本地媒体视频时可用。
- 导入确认框显示文件名；确认后锁定该视频的其他生成命令，展示同一任务的生成状态，并持续说明当前仍展示旧版本。成功后一次刷新转写和概况状态。
- 概况页清晰显示 `人工 SRT`；自动来源继续沿用当前视频处理状态，不恢复含义模糊的旧“有字幕”标识。

### 验收标准

- 导入有效 SRT 后，生成流程不调用 `SubtitleTranscriptProvider` 或任一 ASR 转写器。
- 有效 SRT 和 AI 概况均成功时，两个结果同时成为当前版本；不会出现“新 SRT 配旧概况”或“新概况配旧 SRT”。
- 导入错误 SRT、LLM 失败、任务取消和暂存制品校验失败均不改变现有制品。
- 成功切换后，旧概况、卡片、思维导图和索引不会继续作为有效内容返回。
- 恢复自动转写失败或取消时，原人工版本仍然可用；成功时才回到自动字幕/ASR 链路。

## P1: 时间点截图与查看器

### 用户流程

1. AI 概况生成成功后，系统每章自动抽取一张章节中点插图；没有章节时不生成截图，因为当前概况数据没有可信的全局关键点时间。
2. 概况正文展示缩略图；点击后打开全尺寸模态图片查看器，可关闭，并保持键盘焦点和 Escape 关闭行为。
3. 后续查看或导出同一概况版本时，直接使用已缓存的截图。

### 约束

- 截图属于概况版本的章节插图，原始 transcript 保持纯文本和时间轴数据，也不作为模型重新理解图片的输入。
- 音频媒体没有视频流时跳过截图，照常提交纯文字概况。
- 截图在生成任务中由服务器确定时间点和文件名；客户端只读取已提交的图片 URL。
- 缓存位置为视频制品目录下的 `screenshots/`，文件名按章节序号稳定生成。
- 复用现有 `FfmpegMediaProcessor` 的子进程、错误处理和取消机制；新增“提取单帧”端口方法，不在路由中自行拼装 `subprocess` 调用。
- 抽帧失败或取消不提交本次暂存目录，也不留下空文件。

### 接口与前端

- `GET /api/videos/{series_id}/{video_id}/screenshots/{filename}`：仅返回已提交的 JPEG，拒绝路径穿越。
- 概况章节正文展示自动插图；若本次抽帧失败，整次重生成失败，继续保留旧文字概况与旧插图。
- 图片文件名作为章节附属元数据保存；查看器只保存当前预览等临时前端状态。
- `summary-with-screenshots.zip` 同时包含带相对图片链接的 Markdown 和 `screenshots/` 目录，脱离本地服务后仍可读取。
- 重生成概况、替换/恢复转写、删除视频后，对应旧版本截图随版本失效；物理清理不影响新版本读取。

### 验收标准

- 概况生成后会为每个已定义章节产生确定的一张缓存图；再次查看或导出不启动 ffmpeg。
- 非法秒数和路径穿越输入无法访问输出目录以外的文件。
- 正文插图、全尺寸预览和 Escape 关闭均可用。
- 导出文件在脱离本地服务后仍能加载所有成功生成的图片。
- `概况与截图导出` 仅在当前概况实际包含章节插图时可用。

## P2: 视频库筛选与批量操作

### 状态筛选

保留当前文字搜索，并恢复为明确的状态筛选器：

| 筛选项 | 数据条件 |
| --- | --- |
| 全部 | 不限状态 |
| 已生成 | `processed = true` |
| 未处理 | `processed = false`（包含下载中、链接和无可转写内容） |

筛选只改变当前列表视图，不改变系列顺序或后台任务。筛选结果、空态和计数必须一致。

### 批量管理

- 提供逐项选择、全选当前筛选结果和已选数量提示。
- 批量删除：复用现有单视频删除用例的活动任务检查和索引清理。当前系列存在任一下载中、生成中或其他 doing 阶段的视频时，整体禁用批量删除入口，不允许执行部分删除。
- 仅在系列没有 doing 视频时才允许发起批量删除；执行前再次校验。删除过程中个别视频失败时保留该视频，其他视频继续删除，并返回逐项结果和明确原因。
- 批量生成当前项目已具备“仅处理未处理视频”的系列生成队列，本期不重做、不改变其队列和取消语义。
- 危险操作必须使用现有确认对话框，明确展示视频数量。

### 字幕/转写标识

不恢复旧的 `subtitles-batch` 布尔接口。它实际检查的是 `transcript*.json`，会将 ASR 转写误显示成“有字幕”。

库列表从权威的视频状态/来源字段获取显示信息，并使用 P0 定义的转写来源标签。

### 验收标准

- 状态筛选与文字搜索可以组合；“已生成 / 未处理”与卡片 `processed` 状态一致。
- 系列中存在任一 doing 视频时，批量删除入口不可用，并展示正在处理任务数量；不存在 doing 视频时才可执行，成功删除的视频同步移除 RAG 索引，失败项必须保留并出现在结果列表中。
- 既有批量生成仍只提交未处理项，不受本期改动影响。

## P3: 系列视频排序

### 行为

- 使用成熟的拖拽排序库实现鼠标、触摸和键盘可访问的排序，不复用旧版手写原生拖拽状态。
- 仅在无筛选、无搜索且非批量管理模式下允许排序，避免用户误以为在局部视图中改变了全局顺序。
- 排序后立即持久化；刷新、重新启动和跨前端会话后顺序保持一致。

### 数据与接口

- 在现有系列元数据中保存 `video_order`，值为视频稳定 ID 列表。
- 列表读取时校验并修复顺序：移除不存在的 ID，将新增视频按确定性规则追加到末尾。
- `PUT /api/series/{series_id}/video-order` 接收完整 ID 列表；后端验证集合与当前视频集合完全相等，再原子写入。
- 不允许客户端提交部分顺序、重复 ID 或其他系列的视频 ID。

### 验收标准

- 键盘和指针都能完成排序。
- 并发更新或失效视频 ID 会返回冲突，不会产生半写入的元数据。
- 搜索、筛选或批量模式下排序控制不可用且原因明确。

## 实施顺序

1. P0 后端领域模型、存储、路由和测试，再接前端导入与来源状态。
2. P1 媒体端口和抽帧 API，再接概况截图与查看器。
3. P2 先实现筛选，再实现批量删除；既有批量生成不改动。
4. P3 最后引入拖拽排序库和持久化顺序。

每个工作包完成后运行对应后端单元/集成测试与前端组件测试；P0 和 P1 额外覆盖真实文件制品写入、缓存命中和错误输入。

## 实施状态

- 已完成：P0 手动 SRT、P1 章节截图与导出、P2 `全部 / 已生成 / 未处理` 筛选和受 doing 状态约束的批量删除。
- 待实施：P3 持久化拖拽排序。它需要单独增加排序元数据、API 与成熟拖拽库，尚未混入本次提交。

## 审查决策

实施前需要确认：

1. `transcript.manual.srt` 是否永久保留，还是只保留标准化 JSON。建议保留，便于用户重新上传修订版和追溯来源。
2. 批量删除以系列为单位：存在任一 doing 视频时整体禁用；没有 doing 视频时才允许执行，单项失败时跳过该项并展示原因。
